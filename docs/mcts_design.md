# 순수 MCTS 구현

신경망 없이 게임 종료까지 무작위 대국을 진행하는 C++20 MCTS다. 검증된
`engine/` 파일은 변경하지 않고, `mcts/`에서 기존 `kingdom::State`를 호출한다.
규칙의 기준은 [game_rules.md](game_rules.md)이며, Bitboard 최적화와 신경망
결합은 후속 단계다.

## 공개 API

CMake의 `mcts` 라이브러리와 공개 헤더 `mcts/include/MCTS.h`를 사용한다.
기존 엔진과 같은 `kingdom` 네임스페이스이며, API 좌표는 0부터 시작한다.

```cpp
#include "MCTS.h"

kingdom::State game;
kingdom::MCTSOptions options;
options.simulations = 1000;
options.exploration = 1.4142135623730951;
options.seed = 42;
options.time_limit_ms = 0;

kingdom::MCTS searcher(options);
const auto search = searcher.search(game);
if (search.best_move) {
    const auto outcome = game.play(*search.best_move);
    // outcome.accepted()로 엔진의 최종 수락 여부를 확인한다.
}
```

| 옵션 | 기본값 | 의미 |
| --- | ---: | --- |
| `simulations` | `1000` | 한 탐색에서 수행할 최대 시뮬레이션 수 |
| `exploration` | `sqrt(2)` | UCT 탐색 항의 계수 |
| `seed` | `42` | 의사 난수 생성기의 초기 시드 |
| `time_limit_ms` | `0` | 0이면 시간 제한 없음. 양수이면 완료된 시뮬레이션 사이에서 제한 확인 |

`simulations`는 양수여야 하며, `exploration`은 유한한 0 이상 값이어야 한다.
이 조건을 위반하면 생성자는 `std::invalid_argument`를 던진다.

시간 제한을 사용하더라도 진행 중인 대국을 중간 점수로 평가하지 않는다.
한 시뮬레이션은 게임을 끝까지 진행하므로 지정 시간보다 한 번의 시뮬레이션
만큼 길어질 수 있다. 미종료 상태에서는 최소 한 번의 시뮬레이션을 완료한다.
재현 가능한 비교에는 시간 제한을 끄고 같은 시드와
같은 호출 순서를 사용한다. 동일한 `MCTS` 객체로 다시 탐색하면 난수열이
이어지며, 각 탐색의 트리는 새로 만든다.

`SearchResult`의 결과를 읽어 다음 행동과 탐색 통계를 확인한다.

| 필드 | 의미 |
| --- | --- |
| `best_move` | 추천 수. 종료된 게임에서는 `std::nullopt` |
| `simulations` | 실제 완료한 시뮬레이션 수 |
| `nodes` | 탐색에서 생성한 트리 노드 수 |
| `total_rollout_plies` | 트리 경로 다음의 무작위 대국에서 적용한 총 착수·패스 수 |
| `win_rate` | 추천 수의 관측 승률 |
| `elapsed_seconds` | 실제 탐색 경과 시간(초) |
| `moves` | 실제 확장·수락된 루트 후보의 `MoveStatistics{move, visits, win_rate}` |

`moves`는 좌표 인덱스 순서로 정렬되며 패스는 마지막에 표시된다. 종료된 상태를
탐색하면 추천 수와 후보 목록이 없고 시뮬레이션·노드·무작위 대국 수는 0이다.

승률은 **탐색을 요청한 상태에서 둘 차례인 플레이어**의 관점이다. 예를 들어
백 차례에 탐색하면 백 승리를 1, 흑 승리를 0으로 센다. 추천 수는 방문 횟수가
가장 많은 수이며, 방문 횟수가 같으면 관측 승률을 비교한다. 방문하지 않은
후보의 가능성까지 충분히 평가했다는 뜻은 아니다. 특히 시뮬레이션 수가 후보
수보다 적으면 일부 후보만 탐색하므로 적은 횟수의 결과를 강한 수의 보장으로
해석하지 않는다.

## 한 시뮬레이션의 처리

1. **선택:** 루트 상태를 복사한 뒤 트리 경로의 수를 적용한다. 모두 확장된
   노드에서는 다음 UCT 값이 가장 큰 자식을 고른다.

   ```text
   UCT = 자식의 승리 횟수 / 자식의 방문 횟수
         + exploration * sqrt(log(부모 방문 횟수) / 자식 방문 횟수)
   ```

   각 자식의 승리 횟수는 그 자식으로 가는 수를 **실제로 둔 플레이어**의
   관점으로 저장한다. 상대 차례에는 상대의 승률을 최대화하므로 서로 번갈아
   자기에게 유리한 수를 선택한다.

2. **확장:** 아직 시도하지 않은 후보에서 무작위 순서로 한 수를 적용하고
   자식 노드를 만든다. 코어가 거부하는 후보는 자식으로 만들지 않는다.
3. **무작위 대국:** 그 상태부터 매 차례 합법 수에서 균등하게 하나를 골라
   실제 종료까지 진행한다. 패스와 기본 규칙의 자충수도 후보에 포함한다.
   상대 포획, 자충수 패배, 연속 패스와 집 점수는 기존 엔진이 판정한다.
4. **역전파:** 종료된 대국의 승자를 경로 전체에 전달하여 방문 횟수와
   해당 수를 둔 플레이어의 승리 횟수를 갱신한다.

임의의 대국 길이에서 잘라 현재 집 점수로 승패를 추정하거나, 자충수·패스를
편의상 제외하지 않는다. 이 구현은 무작위 대국 결과를 이용하는 순수 MCTS이며,
신경망이나 전술 우선순위는 사용하지 않는다.

## 기존 엔진을 호출하는 비용

기존 `State::legal_moves()`는 후보마다 상태를 복사해 `play()`를 실행하므로
보드 칸 수를 V라고 할 때 최악 O(V²)다. 이를 매 무작위 턴마다 호출하면
시뮬레이션의 반복 비용이 커진다.

MCTS는 공개된 보드·소유권·돌 재고에서 빈칸, 집 침투 금지와 재고 조건을
O(V)에 확인한다. 이 후보를 적용할 때는 반드시 `State::play()`를 호출하며,
포획·자충수·집·종료 규칙을 다시 구현하지 않는다. 기본 규칙에서는 자충수도
합법이므로 이 사전 조건을 통과한 후보는 합법 수다. 분석용
`SuicideRule::Forbidden`에서는 코어가 거부한 자충수 후보를 제거하고 남은
후보를 다시 선택한다.

상태 전체를 노드마다 보관하는 대신, 노드를 인덱스로 연결한 배열에 담는다.
매 시뮬레이션에서 루트 상태를 한 번 복사하고 선택 경로를 적용하므로 트리
노드 수에 비례하는 전체 상태 복사를 줄인다.

## 시간·공간복잡도

V는 보드 칸 수(81), B는 한 상태의 후보 수(최대 82: 81칸 + 패스), K는
시뮬레이션 수, D는 트리 경로 길이, P는 그 뒤 무작위 대국 길이다.

- 기본 규칙의 한 시뮬레이션은 상한으로 **O(V + D·(B + V) + P·V)**다.
  상태 복사에 O(V), 트리의 UCT 후보 비교와 수 적용에 O(D·(B + V)),
  무작위 대국의 후보 생성과 실제 착수에 O(P·V)가 필요하다.
- K번의 탐색은 각 경로 길이를 합한 비용이며, D와 P를 최대 길이로 잡으면
  **O(K·(V + D·(B + V) + P·V))**로 표시할 수 있다.
- 자충수를 금지하는 분석 변형에서는 거부되는 후보를 여러 번 적용할 수
  있으므로 추가 비용이 발생한다. 한 차례 최악 O(B·V)다.
- 한 시뮬레이션에 최대 한 자식을 생성하므로 노드는 최대 K+1개다. 각 노드의
  후보·자식 목록을 포함한 공간은 상한으로 **O(K·B + V)**다. 경로는 노드의
  부모 인덱스로 추적하므로 별도의 길이 D인 경로 배열은 저장하지 않는다.
- 보드는 9×9로 고정되어 있으므로 위 식은 보드 크기 확장에 관한 API 보장이
  아니라, 현재 구현에서 반복되는 작업량을 비교하기 위한 표기다.

대국 중 돌은 종료 전까지 제거되지 않는다. 각 일반 착수는 빈칸 하나를
채우며, 연속 두 패스는 즉시 종료되므로 완료 대국의 길이에도 유한한 상한이
있다. 데모는 보수적인 최대 164수 한도를 넘어 종료하지 않으면 오류로 보고한다.

## 실행 예제

기존 빌드 명령에 `mcts`와 `mcts_demo` 대상이 함께 포함된다.

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure

# 시작 보드에서 선공의 추천 수를 탐색한다(기본 1000회).
.\build\MCTSDemo.exe
.\build\MCTSDemo.exe 5000

# 양쪽 모두 MCTS로 실제 종료까지 대국한다(기본 수마다 64회).
.\build\MCTSDemo.exe --self-play
.\build\MCTSDemo.exe --self-play 200
```

MSVC처럼 여러 빌드 구성을 지원하면 `build/Release/MCTSDemo.exe`를 사용한다.
추천 수와 자동 대국의 좌표는 사용자 입력 방식과 같은 **1부터 시작하는 행·열**
이며, 패스는 `pass`로 표시한다. `--help`로 사용법을 볼 수 있다.

출력되는 방문 수, 관측 승률, 노드 수, 경과 시간과 초당 시뮬레이션 수는
해당 실행에서 측정한 값이다. 승률은 무작위 대국의 추정치이며 상대의 모든
가능한 대응에 대한 승리 보장이 아니다. 시뮬레이션 속도도 보드 상황, 대국
길이, 탐색 횟수와 하드웨어에 따라 달라진다. 초당 수십만 번이라는 목표의
달성 여부는 별도 벤치마크로 판단한다.

## 검증 결과

2026-10-02 Windows의 GCC 16.2.0 / CMake 3.29.5 / Ninja Release 빌드에서
CTest 5개가 모두 통과했다. MCTS 검증에는 입력 상태 보존, 동일 시드 재현,
후보의 합법성과 방문 수 합계, 양쪽의 포획·상대 관점 선택, 자충수와 집 침투,
패스·종료 상태, 시간 제한, 초기 4,096개 용량을 넘어서는 트리 확장과
고정 시드 5회의 완전한 자가 대국이 포함된다.

실행 예제의 시작 상태 1,000회 탐색과 수당 200회 자동 대국도 실행했다.
자동 대국은 22수 후 백의 상대 돌 포획으로 종료되었다. 작업 전후 `engine/`
내 모든 파일의 SHA-256을 비교하여 변경이 없음을 확인했다.
