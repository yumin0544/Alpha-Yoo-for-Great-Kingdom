# 모델 대결 대시보드

Windows에서 저장소 루트의 **`ModelMatches.cmd`를 더블클릭**하면 대결 화면이
열린다. 기존 게임 화면의 **모델 대결 ↗** 링크로도 이동할 수 있다.
화면과 실제 대결은 현재 프로젝트의 `.venv`, C++ 바인딩과 PyTorch를 사용한다.

```powershell
.\.venv\Scripts\python.exe examples\play_ui.py --open --page matches --port 0
```

`--port 0`은 빈 로컬 포트를 선택한다. 화면에 인쇄된 주소를 사용하고 실행 창은
켜 둔다. 기존 플레이 서버를 켜 둔 경우 이번 변경을 사용하려면 새 실행기를
켜야 한다. 브라우저를 닫거나 새로고침해도 실행 창이 켜져 있으면 대결은
계속된다. 실행 창에서 `Ctrl+C`로 서버를 종료하면 진행 중인 대결에도 중단을
요청하며 현재 탐색이 끝난 뒤 작업자가 종료된다.

## 대결 시작

1. `runs/**/best.pt` 목록에서 서로 다른 모델 A와 B를 선택한다.
2. **전체 대국 수**를 지정한다. 기본 1,000판이며 선후공 균형을 위해 짝수만
   받는다. 2~100,000판을 지원한다.
3. **매 수 탐색 횟수**를 지정한다. 기본 128회이며 양쪽 모델에 동일하게
   적용한다. 수당 1,000회 이상 탐색하려는 경우 이 값을 1,000 이상으로 바꾼다.
   전체 대국 수와 탐색 횟수는 서로 다른 설정이다.
4. CPU 또는 GPU, 시드와 양쪽 전술 검사 적용 여부를 선택한다. 필요하면
   레이팅 설정을 펼쳐 시작 레이팅과 K를 지정한다.
   **동시 대국 수**는 CPU 4판, GPU 12판을 시작점으로 설정한다. 1~64판을
   지원하며 전체 대국 수보다 큰 값은 실제 실행에서 전체 판수로 제한한다.
   화면의 기본 **빠른 배치 탐색**은 판별 추론 배치 16과 트리 재사용을 사용한다.
   **기존 탐색**도 여러 판을 동시에 실행할 수 있다. 기존 순차 조건이 필요하면
   기존 탐색·동시 1판을 선택한다.
5. **대결 시작**을 누른다. 한 서버에서는 한 대결씩 실행한다. 진행 중에는
   다른 기록을 열거나 기보를 확인할 수 있다.

대결은 기존 `examples/model_match.py`를 별도 프로세스로 실행한다. 흑백 교대,
쌍별 시드, 오프닝 샘플링과 레이팅은 [기존 대결 프로토콜](model_match.md)을
그대로 사용한다. GPU 선택은 신경망 추론을 CUDA로 옮기며 규칙 판정과 PUCT
트리는 기존 CPU C++ 경로다. 각 판은 독립적인 탐색 트리를 갖고, 모델별 추론
서비스가 여러 판의 요청을 모아 계산한다. 빠른 방식은 이미 설치된
`BatchedPUCT`의 C++ 인코딩·리프 배치·트리 재사용을 연결한다. `engine/` 파일은
수정하지 않는다. 배치 탐색과 트리 재사용은 방문 분포와 선택 수를 바꿀 수 있으므로
기존 방식의 결과와 동일한 조건으로 취급하지 않는다. 설정은 결과에 함께 저장한다.

1,000판을 한꺼번에 작업 큐에 넣지 않고 동시 대국 수만큼만 실행한다. 한 판이
끝나면 결과를 저장하고 다음 판을 시작한다. 메모리의 활성 탐색 트리 수는 전체
판수에 비례하여 늘어나지 않는다.

모델은 작업 시작 시 읽고 가중치를 고정한다. JSONL의 참가자 정보에 모델 파일과
가중치 해시를 남긴다. 목록은 서버 시작 시 읽으므로 새 모델을 추가하면 실행기를
다시 켠다. 같은 파일을 두 슬롯에 선택하는 요청은 거부한다.

## 결과 확인

- **대결 기록**에서 현재 실행과 과거 대결을 선택한다. 기존 콘솔 프로그램이
  `runs/` 아래에 저장한 스키마 1 JSONL도 자동으로 찾는다. 학습용 `metrics.jsonl`
  또는 성능 벤치마크는 대결 기록으로 읽지 않는다.
- 진행률, 동시 대국 수·진행 중인 판수, 실행 방식, 분당 처리 판수, 경과 시간과
  완료된 판 기준의 예상 남은 시간을 표시한다.
  예상 시간은 초기 모델 준비 시간과 앞으로 달라지는 판 길이 때문에 변할 수 있다.
- A/B 승패·누적 승률, 흑/백별 승률, 종료 사유, 평균 수순을 표시한다. 진행 중
  선후공별 분모는 **실제로 완료된 판수**이며 아직 치르지 않은 판은 포함하지 않는다.
- 누적 승률 차트는 전체 완료 대국을 기준으로 계산하며 최대 약 200개 지점으로
  화면에 표시한다. 병렬 실행에서는 완료된 순서로 누적하며, 판별 결과·CSV는
  고정된 판 번호로 정렬한다. 조회 시 모든 기보를 브라우저로 보내지 않는다.
- **내부 시리즈 레이팅**은 전체 대결이 정상 완료되어 저장된 `summary`가 확인될
  때만 표시한다. 진행 중·중단·실패한 대결에는 레이팅을 적용하지 않는다.
  고정 K를 전체 대결에 한 번 적용하는 내부 비교값이다.
- **판별 결과**는 25판씩 조회한다. 승자·종료 사유·A의 선후공으로 필터링한다.
  **보기 ↗**를 누르면 처음부터 마지막까지 방향 버튼과 슬라이더로 기보를 본다.
  기보는 기존 C++ 규칙 엔진으로 다시 실행하여 집과 승패를 확인한다.
- **CSV ↓**는 모델 이름·탐색 설정과 판별 결과를 Excel에서 읽기 쉬운 UTF-8 BOM
  CSV로 내려받는다. **기보 ↓**는 참가자·설정·수순과 최종 결과를 포함한 원본
  JSONL 형식이다. 진행 중에는 저장 완료된 행까지만 내보낸다.

## 중단과 저장

**대결 중단**은 화면의 확인 창에서 실행한다. 새 판의 시작을 막고 실행 중인
각 판의 현재 한 수 탐색이 완료되면 중단한다. 완료된 판은 보존하고, 진행 중이던 판은
완료 결과로 세지 않는다. 중단 뒤 새 대결을 시작할 수 있다. 같은 대결의
자동 재개 기능은 제공하지 않는다.

UI에서 시작한 대결은 `runs/matches/날짜-고유번호/`에 저장한다.

| 파일 | 내용 |
| --- | --- |
| `request.json` | 선택한 참가자·시작 설정과 준비 단계 오류 |
| `results.jsonl` | 기존 CLI의 `session`, 매 판 `game`, 정상 완료 `summary` 또는 `aborted` |
| `progress.json` | 진행 중인 판 목록·수순·작업자 수와 경과 시간; 약 1초 간격 및 판 시작 시 갱신 |
| `worker.log` | 실행 출력과 오류 진단 |
| `stop.request` | 중단 요청이 있을 때 생성 |

실행기를 다시 켜면 저장 결과를 다시 볼 수 있다. 완료 기록이 없는 외부 CLI
대결 또는 서버가 비정상 종료된 일부 결과는 **일부 기록**으로 표시한다. 그런
파일도 완료된 판의 통계와 기보를 볼 수 있고, 파일에 판이 추가되면 화면을
갱신한다. 현재 서버에서 시작하지 않은 프로세스는 중단하지 않는다.

서버는 `127.0.0.1`에만 연결한다. 실행 요청은 같은 화면의 Origin·서버 식별자를
검증하며 모델 목록과 저장 기록 ID 밖의 임의 경로를 받지 않는다.

## 검증

`tests/arena_ui_test.py`는 1,024개의 규칙상 유효한 시험 결과로 통계·페이지·
필터·차트 크기·내보내기·순서가 뒤바뀐 판의 복기를 확인하고, 작은 실제 저장
모델로 병렬 CLI 실행 완료·중단·실패 복구·기보·HTTP 경로를 확인한다.
`tests/model_match_test.py`는 1,000판 요청에서도 활성 작업 수가 제한되는지,
먼저 완료된 결과가 저장되는지, 추론·표시 오류 시 모든 작업자가 종료되는지 확인한다.
1,024개 결과의 조회 검증은
학습 모델끼리 1,024판을 실제 탐색한 성능 측정과 구분한다.

```powershell
$env:PYTHONPATH='python'
.\.venv\Scripts\python.exe tests\arena_ui_test.py
```

`BUILD_NEURAL_TESTS=ON`인 구성에서 CTest에도 등록한다.

## 병렬 성능 측정 (2026-10-07)

RTX 3050, PyTorch 2.9.1+cu126, CPU 추론 스레드 1에서 `champion_128v`와
`champion_171v`를 비교했다. 같은 시드 42·오프닝 6수·전술 검사 꺼짐·수당
128회로 각각 12판을 실행했다. 모델을 미리 읽고 GPU를 준비한 뒤 대결 실행만
측정했으며, 아래 시간에는 체크포인트 로딩과 프로세스 시작 시간이 포함되지 않는다.

| 실행 방식 | 동시 대국 | 시간 | 전체 수순 |
| --- | ---: | ---: | ---: |
| 기존 순차 탐색 | 1 | 135.253초 | 334 |
| 기존 탐색·공유 추론 배치 | 12 | 64.105초 | 334 |
| 빠른 배치 탐색·배치 16·트리 재사용 | 4 | 4.651초 | 368 |
| 빠른 배치 탐색·배치 16·트리 재사용 | 12 | 2.693초 | 368 |

빠른 방식은 기존 방식과 탐색 방문 분포가 다르다. 시간 비율은 **해당 설정의
실제 대결 처리량**이며, 같은 수순·같은 신경망 평가 횟수의 순수 연산 속도
비교가 아니다. 짧은 12판 표본의 속도를 1,000판 실행 시간으로 보장하지 않는다.

추가로 UI에서 같은 두 모델을 **수당 16회·동시 12판·빠른 배치 16·트리 재사용**으로
1,000판 실제 실행하여 24.757초에 정상 완료했다. 총 17,389수이며 1,000개의
기보를 기존 규칙 엔진으로 재생해 최종 보드·승자·종료 사유·집 점수를 확인했다.
판 번호는 1~1,000에 중복·누락이 없고 A의 흑/백은 각각 500판이다. 이 측정은
수당 128회 실험과 별개이며, 낮은 탐색 예산의 검증 결과를 기력 평가로 해석하지 않는다.

별도 UI 중단 검증에서는 수당 128회·전술 검사 켜짐·동시 12판으로 실행하여
135판 완료 후 중단했다. 완료한 135판은 보존되었고 전체 시리즈 레이팅은
적용되지 않았다.

로컬 원자료는 `build-parallel/match-parallel-check/benchmark.json`과
`runs/matches/20261007-123212-c70d4e49/results.jsonl`에 있다. 로컬 실행 결과는
Git에 포함하지 않는다.
