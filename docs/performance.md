# 처리 속도 실측: 2026-10-02

설치된 Python 바인딩을 통해 C++ MCTS가 양쪽의 수를 선택하고, 기본 보드에서
실제 게임 종료까지 진행했다. 완료 대국 수와 탐색 내부 시뮬레이션 수는 구분한다.

## 측정 조건

- Windows 11 x64, CPython 3.14.8, MSVC 19.41 Release (`/O2`), pybind11 3.1.0.
- 프로세서 식별자: `Intel64 Family 6 Model 126 Stepping 5, GenuineIntel`.
- 작업 스레드 1개, 신경망 없이 현재 배열 보드와 순수 MCTS 사용.
- 기본 규칙, 중앙 중립 돌, 난수 시드 42, 시간 제한 없음.
- 설정별 준비 대국 1판을 제외하고 실제 20판을 측정했다. 측정 대상 탐색 객체는
  시드 42로 새로 생성하며, 20판 동안 난수 상태를 이어서 사용한다.
- 시간에는 상태 생성, 모든 수의 MCTS 탐색, Python/C++ 왕복 호출과 착수를 포함한다.
  모듈 로드, 준비 대국, 결과 출력 시간은 제외한다.
- 수순 수에는 양쪽 착수와 패스가 각각 한 수로 포함된다.

## 실제 완료 대국

| 수마다 탐색 횟수 | 완료 대국 | 총 시간 | 초당 대국 | 한 판 평균 시간 | 평균 수순 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 64 | 20판 | 2.230초 | 8.969판 | 0.1115초 | 12.3수 |
| 1,000 | 20판 | 67.738초 | 0.295판 | 3.3869초 | 22.3수 |

두 설정 모두 20판이 상대 돌 포획으로 종료됐다. 이 결과는 현재 탐색 정책과
대국 길이에 대한 처리량이며, 대국 수준이나 더 긴 대국의 처리량을 보장하지 않는다.

64회 설정에서는 총 15,744회, 1,000회 설정에서는 총 446,000회의 내부 탐색을
실행했다. 전체 대국 시간 기준 내부 시뮬레이션 처리량은 각각 약 7,060회/초와
6,584회/초였다. 이 내부 시뮬레이션을 별도의 완료 자가 대국으로 세지 않는다.

## 초기 보드에서 한 수 탐색

별도로 초기 보드에서 10,000회 탐색한 결과는 다음과 같다.

- 경과 시간: 1.7797초, 시뮬레이션 처리량: 약 5,619회/초.
- 생성 노드: 10,001개, 시뮬레이션당 평균 무작위 플레이아웃 길이: 44.7574수.
- 무작위 플레이아웃 길이는 탐색 트리에서 이미 적용한 수순을 제외한 통계다.

초당 수십만 회 시뮬레이션은 개발 목표이며 현재 측정 결과는 그에 도달하지 않았다.
신경망 추론을 포함한 학습 처리량과 Bitboard 최적화 후 성능은 별도로 측정해야 한다.

## 병렬 자가 대국 실측: 2026-10-05

`examples/python_benchmark.py`에 `--workers`와 `--repeats`를 추가했다.
Python 스레드 작업자는 대국마다 별도의 `State`와 `MCTS`를 생성한다.
기존 바인딩이 C++ 탐색 중 GIL을 해제하므로 여러 코어에서 탐색할 수 있다.
같은 `MCTS` 객체의 잠금은 공유하지 않으며, `engine/` 소스는 변경하지 않았다.

### 환경과 공정한 비교

- 사용자 제공 CPU 사양: 6코어·12스레드, 3.7GHz. Python에서 논리 CPU 12개를 확인했다.
- Windows 11 x64, CPython 3.12.14, MSYS2 UCRT64 GCC 16.2.0,
  CMake Release 빌드, pybind11 3.1.0. 신경망 없이 기본 규칙의 순수 MCTS를 사용한다.
- 판 번호 `i`에 대해 시드는 `(42 + i) % 2**64`이며, 각 판에 새 탐색 객체를 만든다.
  따라서 작업자 수에 관계없이 동일한 판 목록을 실행한다. 앞의 2026-10-02
  기록은 한 탐색 객체의 난수 상태를 계속 사용하므로 그 판 목록과는 다르다.
- 준비 대국 한 판과 모듈 로드는 시간에서 제외한다. 스레드 풀 생성·종료,
  대국 제출, 상태와 탐색 객체 생성, 실제 착수, 결과 집계·검증값 계산은 포함한다.
- 출력의 `seconds_per_game`은 전체 경과 시간/완료 판수인 **한 판당 환산 시간**이다.
  병렬 대국 하나의 지연 시간을 측정한 값은 아니다.
- 작업자 수별로 승자·종료 사유·수순·탐색 횟수·최종 보드의 SHA-256이 같아야 한다.
  다르면 프로그램이 오류로 종료한다. 무작위 플레이아웃 횟수를 완료 판수로 세지 않는다.

### 실행과 검증

이 머신의 측정 설정에서는 작업자 12개가 가장 빨랐다.

```powershell
# 총 1000판을 최대 12판씩 동시에 실행한다.
.\.venv\Scripts\python.exe examples\python_benchmark.py --games 1000 --simulations 64 --workers 12
# 같은 판 목록으로 작업자 수를 비교하고 3회 중앙값을 구한다.
.\.venv\Scripts\python.exe examples\python_benchmark.py --games 240 --simulations 64 --workers 1 2 4 6 12 --repeats 3
.\.venv\Scripts\python.exe tests\parallel_benchmark_test.py
```

`--workers` 기본값은 1이다. 여러 숫자를 주면 설정을 순서대로 측정하며,
반복 측정의 시작 설정을 순환한다. 요청 작업자 수가 판수보다 크면 판수로 제한한다.
JSON의 `scaling_summary`는 각 설정 중앙값, 단일 작업자 대비 향상과
실측상 가장 빠른 작업자 수를 출력한다. 짧은 측정에서는 부하에 따라 값이 달라질 수 있다.

병렬 검증 테스트 6개는 작업자 1·2·4·6개의 대국 결과 일치, 정확한 판수와 탐색량,
64비트 시드 범위 순환, 판수보다 많은 작업자, 작업 중 오류 전파와 잘못된 설정 거부를
확인한다. `parallel_benchmark_test`는 Python 바인딩을 켠 CTest에도 등록했다.
GCC Release 검증 빌드에서 CTest 7개 묶음이 모두 통과했으며, Python 바인딩의
C++ 참조 결과 비교도 포함했다. 검증 빌드 경로의 한글을 GNU `strip`이 처리하지
못해 해당 빌드에만 `-DCMAKE_STRIP=`를 지정하고 GCC 런타임 DLL을 출력 폴더에
복사했다. 성능 측정은 앞서 설치한 Release 바인딩으로 수행했다.
이 실행기는 순수 MCTS의 병렬 자가 대국용이며, 기존 신경망 강화학습 `Trainer`의
자가 대국·학습 루프는 계속 순차 실행한다.

## RTX 3050 신경망 PUCT 비교: 2026-10-05

CUDA용 PyTorch 2.9.1+cu126과 NumPy를 설치하고, RTX 3050 8GB에서 실제 CUDA
연산과 배치 평가를 검증했다. 드라이버는 566.14다. 배치 서비스의 API와 설치
명령, 측정 시간의 범위는 [GPU 배치 추론 안내](gpu_benchmark.md)에 기록한다.

비교 대상은 순수 MCTS가 아닌 신경망 PUCT다. 시드 42의 동일한 초기 가중치
(32채널, 잔차 블록 2개, 56,189개 파라미터)를 사용했다. FP32이며 TF32와
혼합 정밀도는 끈다. 각 설정은 24판을 수당 32회 탐색하며, 12개 대국 작업자와
PyTorch CPU 연산 스레드 1개를 사용한다. 준비 추론·모델 복사를 제외하고
CPU/GPU 왕복과 실제 완료 대국 시간을 모두 포함하여 세 번 측정한다.
배치 상한은 1 또는 12이며 추가 요청 대기는 0ms다.

```powershell
.\.venv\Scripts\python.exe examples\gpu_benchmark.py --games 24 --simulations 32 --workers 12 --batch-sizes 1 12 --cpu-threads 1 --repeats 3 --inference-iterations 200
```

원본 측정값은 [GPU 비교 JSONL](benchmarks/gpu_32_2026-10-05.jsonl)에 저장한다.
이 초기 모델은 처리량 측정용이며 기력이나 학습 개선을 검증한 결과는 아니다.

### CPU 신경망 연산 12스레드 실측: 2026-10-05

위 측정의 대국 작업자 12개와 신경망 CPU 연산 스레드 1개를 구분하기 위해,
PyTorch CPU intra-op 스레드를 1개와 12개로 바꾸어 실제 대국을 다시 실행했다.
별도 Python 작업자에서도 `torch.get_num_threads()`가 각각 1과 12임을 확인했다.
대국 작업자 12개와 연산 스레드 12개는 별개 설정이며 전체 OS 스레드 수를
정확히 12개로 제한하는 설정은 아니다.

동일한 모델 가중치·시드·FP32와 수당 32회 탐색을 사용했다. 배치 상한은 12,
대기 시간은 0ms이며 각 설정에서 24판씩 3회 완료했다. 총 288판을 측정했고,
설정의 시작 순서는 반복마다 순환했다.

```powershell
.\.venv\Scripts\python.exe examples\gpu_benchmark.py --devices cpu cuda --cpu-threads 1 12 --workers 12 --batch-sizes 12 --games 24 --simulations 32 --repeats 3 --inference-iterations 200
```

약 32.0% 낮았다. GPU 추론에서도 CPU 연산 스레드 12개 설정의 처리량은
1개 설정의 0.748배였다. GPU 설정의 CPU 연산 스레드는 CPU 인코딩·출력
마스킹 등에 적용되며, GPU의 CUDA 실행 스레드 수를 지정하지 않는다.
이 비교에서 가장 빠른 설정은 대국 작업자 12개와 CPU 신경망 연산 스레드
1개를 사용하는 CPU 배치였다.

모든 12개 실행에서 같은 24판의 수순·승자·최종 보드 체크섬이 일치했다.
실행당 평균 30.0417수, 트리 시뮬레이션 23,072회, 신경망 평가 23,325회,
포획 종료 23판·연속 패스 종료 1판, 흑 13승·백 11승이었다.
실제 평균 배치 크기는 약 4.35였다. 원본은
[CPU 연산 스레드 1/12 비교 JSONL](benchmarks/gpu_cpu_threads_12_2026-10-05.jsonl)에 저장했다.

**이 표의 GPU 실행은 CPU PUCT와 GPU 신경망 추론을 결합한 측정이다.**
이 측정 당시에는 전체 PUCT의 트리 선택·확장·역전파와 규칙 판정을 GPU에서
수행하는 구현이 없어 전체 GPU PUCT 처리량을 측정하지 않았다. 이후 기존
`engine/`를 유지하면서 GPU 규칙·상태·트리·인코딩을 별도로 구현했다.
현재 API와 검증 범위는 [GPU PUCT 안내](gpu_puct.md)에 기록한다.

### 기존 순수 MCTS 처리량 재확인: 2026-10-05

기존 순수 MCTS의 4.391판/초와 신경망 PUCT의 0.798판/초는 탐색 방식과
연산 스레드 설정이 다른 결과다. 기존 4.391판/초는 신경망 없이 수당 1,000회
탐색하고 12개 대국 작업자를 사용한 값이다. PUCT는 수당 32회 탐색하고
같은 12개 대국 작업자에 PyTorch CPU 연산 스레드 12개를 추가한다.
PUCT에는 CPU 인코딩·신경망 추론·콜백·배치 요청 처리가 포함되며,
한 판당 평균 약 972회 신경망 평가를 수행했다. 평균 대국 길이도 순수 MCTS
23.3542수와 PUCT 30.0417수로 다르다. 두 탐색의 시뮬레이션 횟수를 같은
연산량으로 해석할 수 없다.

기존 MCTS 실행기를 현재 환경에서 원래와 같은 48판·수당 1,000회·대국
작업자 12개로 3회 재측정했다. 처리량은 4.521, 4.477, 4.492판/초였고
중앙값은 **4.492판/초**였다. 세 번 모두 기존 기록과 수순·승자·최종 보드
체크섬이 일치했다. 같은 실행기의 처리량이 0.798판/초로 저하된 결과는 아니다.
원본은 [순수 MCTS 재확인 JSONL](benchmarks/pure_mcts_recheck_1000_2026-10-05.jsonl)에 저장했다.

```powershell
.\.venv\Scripts\python.exe examples\python_benchmark.py --games 48 --simulations 1000 --workers 12 --repeats 3
```

동일한 PUCT 설정에서 CPU 연산 스레드 1개 대비 12개 설정의 처리량이 약
32% 낮아진 것은 실측값이다. 스레드 관리·경쟁, Python GIL과 요청 대기의
원인별 시간 비중은 별도 프로파일링을 하지 않아 확정하지 않았다.

## GPU 규칙·트리·신경망 PUCT 실측: 2026-10-05

`GpuStateBatch`와 `GpuPUCT`를 추가해 규칙 판정·입력 인코딩·트리 선택·확장·
역전파·신경망 추론을 CUDA에서 수행했다. `engine/`는 변경하지 않았다.
API와 호스트 호출·동기화 범위는 [GPU PUCT 안내](gpu_puct.md)에 기록한다.

RTX 3050 8GB, PyTorch 2.9.1+cu126, NVRTC 12.6의 `compute_86` 커널을 사용했다.
모델은 앞선 실험과 같은 시드 42의 32채널·잔차 블록 2개·56,189개 파라미터와
가중치 SHA-256을 사용한다. 신경망은 FP32, 트리 사전 확률·값 누적은 FP64,
TF32는 껐다. 모든 대국은 수당 32회 탐색했다. 루트 잡음을 0으로 설정해 CPU와
GPU의 난수 생성기 차이를 제거했다. 앞선 잡음 0.25 측정과 조건이 다르므로
앞선 0.798판/초나 0.886판/초를 이 실험의 CPU/GPU 기준으로 사용하지 않는다.

### 같은 24판: CPU 12개 작업자와 GPU 배치 12·24개

각 설정에서 24판씩 3회, 총 216판을 완료했다. CPU는 대국 작업자 12개와
PyTorch CPU 연산 스레드 1개를 사용했다. GPU는 12개 또는 24개의 대국을
함께 탐색했다. 준비·컴파일·모델 복사·준비 탐색을 제외하고 실제 대국 완료와
GPU 결과 회수·집계를 포함한다. CPU 엔진을 이용한 GPU 착수 기록 재현 검증은
시간 측정 후 수행하고 별도 시간을 출력한다.

```powershell
.\.venv\Scripts\python.exe examples\gpu_puct_benchmark.py --games 24 --simulations 32 --workers 12 --gpu-batch-sizes 12 24 --repeats 3
```

모든 9개 실행에서 착수 기록·최종 상태가 일치했다. 평균 32수, 실행당 총

## GPU Trainer 연결과 실제 반복 학습: 2026-10-05

설치한 패키지에서 소스 경로 지정 없이 GPU 자가 대국·CPU FIFO 자료 버퍼·
CUDA Adam 학습·흑백 교대 평가·기준 모델 승격·저장과 재개를 실행했다.
RTX 3050 8GB, PyTorch 2.9.1+cu126에서 32채널·잔차 블록 2개 모델을 사용했다.
자가 대국은 128판 배치, 수당 32회 탐색, 루트 잡음 비율 0.25, 착수 온도 1이다.
반복마다 위치 64개 미니배치로 8회 갱신하고, 기존 C++ PUCT와 CUDA 신경망으로
흑백 교대 평가 2판을 수당 32회 탐색했다. PyTorch CPU 스레드는 1개다.
실제 CLI 기본 설정을 사용해 cuDNN TF32는 켜고 matmul TF32는 껐으며,
cuDNN deterministic과 benchmark는 모두 껐다.

첫 프로세스에서 2회를 완료한 후 종료하고, `latest.pt`를 읽은 새 프로세스에서
1회를 추가 완료했다. 총 자가 대국 384판, 평가 6판, 가중치 갱신 24회,
착수 전 학습 위치 10,001개를 만들고 FIFO 버퍼에 최신 10,000개를 보관했다.
두 번째 반복에서 승격한 기준 모델을 세 번째 반복의 자료 생성에 사용했다.
저장된 learner 가중치의 실제 변경, optimizer·버퍼·진행 횟수 복원과
`best.pt`가 저장된 champion 가중치와 일치함을 확인했다.

| 반복 | 자료 생성·버퍼 저장 | 자료 생성 판/초 | 가중치 갱신 | 평가 | 전체 반복 | 반복 판/초 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 14.303초 | 8.949 | 0.413초 | 1.438초 | 16.154초 | 7.924 |
| 2 | 11.199초 | 11.429 | 0.245초 | 4.849초 | 16.294초 | 7.856 |
| 3: 재개 | 14.012초 | 9.135 | 0.398초 | 0.969초 | 15.379초 | 8.323 |

각 자료 생성 시간에는 GPU 탐색·착수, 학습용 입력·정책 이력 수집, CPU 회수와
버퍼 검증·저장이 포함된다. 최초 반복과 새 프로세스의 재개 반복에는 CUDA
커널 준비도 포함된다. 전체 반복 시간에는 가중치 갱신과 평가를 더하지만
체크포인트·기준 모델 파일 저장, 지표 기록과 프로세스 시작은 제외한다.
이 항목까지 포함한 실제 CLI 경과 시간은 첫 2회 44.189초, 재개 1회 27.566초,
합계 71.755초로 자가 대국 판수 기준 **5.35판/초**였다.

이는 서로 다른 자료·가중치·평가 수순의 3회 실제 학습 실행이며 동일 조건의
독립 벤치마크 3회 평균이나 기력 향상 검증은 아니다. 평가 2판은 통합 검사
예산으로 사용했다. 잡음 없는 GPU 자가 대국 36.788판/초 측정과 수행 작업,
난수·수순·TF32 조건이 달라 직접 향상률이나 원인별 비용을 계산하지 않는다.
실행 명령·설정·단계별 지표·CLI 전체 시간은
[GPU Trainer 검증 JSONL](benchmarks/trainer_gpu_2026-10-05.jsonl)에 있다.

GPU 자료 생성 검사 6개와 Trainer 연결 검사 5개를 추가한 CTest 17개 묶음이
모두 통과했다. 별도 동일 설정의 결정적 CUDA 테스트에서 연속 2회와 1회 저장
후 재개의 자료·미니배치·가중치·Adam·버퍼·난수 상태가 정확히 일치했다.
CUDA 체크포인트는 `--device cuda`로 재개하며, 예전 버전 1의 CPU 체크포인트도
복원한다. `engine/`는 변경하지 않았다. 실행 안내는
[반복 학습 안내](training_loop.md)에 기록한다.
