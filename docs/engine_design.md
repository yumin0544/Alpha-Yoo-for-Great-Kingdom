# 엔진 개발 계획

사용자가 2026-10-02에 지정한 개발 순서다. 규칙의 기준 문서는 [game_rules.md](game_rules.md)다.

## 1단계: C++ 엔진 코어와 순수 MCTS

- 9×9 보드, 선후공, 중앙 중립 돌, 턴, 패스, 종료 상태를 표현한다.
- 돌을 놓는 함수와 합법 착수 판정, 집 판정, 상대 돌 무리의 포위 판정, 즉시 승리와 연속 패스 후 점수 판정을 구현한다.
- 양쪽 동시 포위 시 착수자가 승리하는 우선순위를 지킨다.
- 신경망 없이 무작위 플레이아웃을 사용하는 순수 MCTS를 C++로 구현한다.
- 배열 보드의 규칙 정확성을 먼저 검증하고, 81개 지점을 비트 연산으로 처리하는 Bitboard 최적화를 적용한다. 81비트는 하나의 64비트 정수에 들어가지 않으므로 여러 워드 등 적절한 표현을 선택한다.
- 규칙 문서의 예시와 후속 확정을 기준으로 검증한다. 일반 바둑의 패, 사활, 포획 후 대국 지속을 임의로 추가하지 않는다.

## 2단계: pybind11 Python 바인딩

- C++ 코어를 pybind11로 감싸 Python에서 `import my_board_engine`으로 호출한다.
- 플랫폼에 맞게 `.pyd` 또는 `.so`를 빌드한다.
- Python에서도 C++과 동일한 상태, 착수, 합법 수, 종료 및 승패 판정을 사용한다.

2026-10-02에 Windows CPython 3.14.8용 모듈 빌드·설치, CTest 6개 묶음,
Python 15개 사례와 C++ 결과 비교를 검증했다. 사용 예제와 검증 환경은
[Python 바인딩 안내](python_bindings.md)에 기록한다.
- `bindings/module.cpp`는 코어와 순수 MCTS의 공개 API를 감싸며 `engine/`를 변경하지 않는다.
- `pyproject.toml`의 scikit-build-core 구성으로 `python -m pip install .`을 지원한다.
  CMake의 `BUILD_PYTHON_BINDINGS` 기본값은 꺼져 있어 기존 C++ 빌드에는 Python이 필요 없다.
- 상태 조회는 사본을 반환하고, MCTS는 호출 시 상태를 복사한 뒤 C++ 탐색 동안
  Python GIL을 해제한다. 진행 중인 대국의 완전한 복사는 `State.copy()`로 수행한다.
- Python 사용 예제는 `examples/python_demo.py`, API와 설치 안내는
  [python_bindings.md](python_bindings.md)에 기록한다.

## 3단계: Python + PyTorch 신경망과 강화학습

- `python/kingdom_ai/`에 PyTorch 정책·가치 신경망을 구성한다.
- Python 학습 코드가 C++ 엔진을 호출하며 수십만 번의 대국을 생성하고 강화학습을 진행한다.
- 학습된 모델을 저장하고 대국 결과와 성능을 기록한다.

2026-10-02에 입력·출력 스키마 1과 모델 연결을 구현한다. 입력은 현재 차례의
플레이어 관점에서 돌, 중립 돌, 확정 집, 선공 여부, 돌 재고, 패스 횟수와 합법
착수를 표현하는 `[N, 10, 9, 9]` 텐서다. 정책은 81개 보드 지점과 패스의
점수 `[N, 82]`, 가치는 현재 플레이어 관점의 `[N]` 평가값을 출력한다.

기본 모델은 합성곱과 GroupNorm, 잔차 블록, 정책·가치 출력을 사용한다.
`NeuralAgent`는 C++ 합법 수 마스크로 정책을 정규화하고 엔진에 적용할 수 있는
추천 수를 반환한다. 초기 모델 연결 단계에서는 기존 C++ MCTS의 순수 무작위
탐색을 유지했다. 이후 아래 PUCT 단계에서 신경망 탐색을 별도로 연결한다.
`engine/` 파일은 변경하지 않는다.

종료까지 진행한 순수 MCTS 대국에서 착수 전 상태, 후보 방문 수와 최종 승자를
모아 학습 자료를 생성한다. 방문 비율은 정책 목표, 착수 전 플레이어의 최종
승패는 가치 목표다. 한 번의 갱신과 스키마·모델 구성·가중치 저장 및 복원을

[neural_network.md](neural_network.md)에 기록한다.

신경망 정책과 가치를 사용하는 PUCT 탐색과 자가 대국 자료 생성을 구현한다.

## 기본 엔진 구현: 2026-10-02

위 절은 규칙을 처음 저장할 당시의 기록이다. 현재 기본 엔진은 C++20 배열 보드로 구현하며, Bitboard 최적화는 다음 단계로 남긴다. 순수 MCTS는 별도 `mcts/`에 구현한다. 외부 라이브러리 없이 CMake로 코어, MCTS, 예제와 독립 테스트를 빌드한다.

### 공개 API

- 네임스페이스는 `kingdom`, 공개 헤더 위치는 `engine/include/board`다.
- `Board`는 9×9 칸, 상하좌우 이웃, 연결된 돌 무리와 빈 이웃을 표현한다. `to_string()`은 `x/o/v/.`로 보드를 출력한다.
- `State(GameRules rules = {}, std::optional<Position> neutral = Position{4, 4})`로 시작한다. 기본 중립 돌은 중앙이며, 다른 좌표 또는 `std::nullopt`로 숙련자 변형을 설정할 수 있다.
- `State::play(Move::place(row, col))` 또는 `State::play(Move::pass())`로 진행한다. 반환값 `MoveOutcome::accepted()`로 수락 여부를 확인한다. 거부된 착수는 보드와 턴을 바꾸지 않는다.
- API 좌표는 **0부터 시작**한다. 따라서 규칙 문서의 (5행, 5열)은 API의 `{4, 4}`다.
- `State::score()`는 현재 빈 집 칸 수인 `Score{black, white}`를 반환한다. 중립 돌은 점수에 포함하지 않으며, 기본 규칙에서는 자기 집과 상대 집 모두 착수가 금지된다.
- `State::result().finished()`로 종료 여부를 확인하고, `State::result()`에서 승자와 종료 사유를 읽는다. 대국 중에는 종료 사유가 `EndReason::None`이다. 연속 패스 판정은 `black - white >= 3`이면 흑 승리, 그 외에는 백 승리다.

### 판정 순서와 집의 소유권

착수 가능 여부를 확인한 뒤 상대 돌의 포획을 먼저 확인한다. 상대를 포획하면 즉시 착수자 승리이며, 자기 돌의 포위 여부가 이를 뒤집지 않는다. 상대 포획이 없는 자충수는 착수를 수락하고 상대 승리로 즉시 종료한다. 포획과 자충수가 모두 없는 경우 집을 갱신한다. 완성된 집의 소유권은 상태에 보존하며, 자기 집과 상대 집 모두 새 착수를 금지한다. 빈칸 영역의 경계에 상대 돌이 있거나, 네 가장자리 모두에 닿거나, 소유자의 돌 경계가 없으면 새 집으로 인정하지 않는다.

### 확정된 기본값과 분석용 옵션

사용자 후속 지시로 자기 집 안 착수 금지, 각자 41개, 한 가장자리 집 인정, 자충수 허용 후 즉시 패배가 모두 확정되었다. `GameRules`에서 확정 기본값을 바꾸면 분석용 변형이며 기본 규칙과 구분한다.

| 옵션 | 기본값 | 구현 동작 |
| --- | --- | --- |
| `suicide_rule` | `SuicideRule::Loses` | 확정: 상대를 포획하지 못하는 자충수를 수락하고 상대 승리로 즉시 종료한다. 분석용 변형인 `SuicideRule::Forbidden`은 자충수를 거부한다. 양쪽 동시 포위 시에는 항상 상대 포획에 따른 착수자 승리가 먼저 적용된다. |
| `allow_own_territory_moves` | `false` | 확정: 자기 집 안 착수를 금지한다. 분석용으로 `true`를 설정하면 허용하되 빈칸 점수만 센다. |
| `allow_single_edge_territory` | `true` | 확정: 한 가장자리만 이용하는 집도 허용한다. 네 가장자리 모두를 이용하는 영역은 항상 제외한다. |
| `stones_per_player` | `41` | 확정: 각자 41개다. 돌을 모두 사용하면 패스만 허용하며, 중립 돌 위치 변경과 중립 돌 없는 변형에도 같은 기본값을 적용한다. |

### 빌드와 검증 방법

```sh
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

`board_test`, `capture_test`, `territory_test`는 보드/턴, 포획 우선순위, 집과 종료 판정을 검증한다. `demo`는 기본 보드 출력, 착수, 연속 패스 종료를 보여준다. 성능 달성 수치는 실제 벤치마크 수행 후 기록한다.

### 사용자가 양쪽을 입력하는 대국 실행파일

`examples/play.cpp`의 콘솔 대국 프로그램을 CMake의 `great_kingdom` 대상으로 빌드한다. Windows 실행파일 이름은 `GreatKingdom.exe`다. 단일 구성 빌드는 `build/GreatKingdom.exe`, MSVC 등 다중 구성의 Release 빌드는 `build/Release/GreatKingdom.exe`를 실행한다. 실행파일을 더블클릭하면 대국 창이 열린다. Windows GCC 빌드에서는 표준 런타임을 정적으로 연결하므로 실행 시 별도로 설치할 필요가 없다.

사용자가 선공과 후공을 모두 조작하며 AI는 연결하지 않는다. 기본 `State`를 사용하므로 중앙 중립 돌, 각자 41개, 자기 집과 상대 집 착수 금지, 자충수 허용 후 즉시 패배와 선공의 3칸 차이 승리 조건을 그대로 따른다. 기존 `demo`는 자동 진행 예제로 유지한다.

- `3 4`처럼 **1부터 시작하는 행과 열**을 입력하여 현재 플레이어의 돌을 놓는다.
- `pass` 또는 `패스`로 차례를 넘긴다.
- `help` 또는 `도움말`로 입력 방법을 보고, `quit`, `q` 또는 `종료`로 끝낸다.
- 보드 기호는 `x`(선공), `o`(후공), `#`(중립 돌), `B`(선공의 완성된 빈 집), `W`(후공의 완성된 빈 집), `.`(미확정 빈칸)이다. 코어의 `Board::to_string()` 표기와 달리 콘솔 화면은 집의 소유권도 함께 표시한다.
- 수락된 착수와 패스 후 보드, 차례, 남은 돌과 현재 집 점수를 표시한다. 거부된 착수는 사유를 표시하고 같은 플레이어의 입력을 다시 받는다.
- 종료 시 포획, 자충수 또는 연속 패스 사유와 승자를 표시한다. `r`로 새 대국을 시작하고 `q`로 종료하며, 입력 종료(EOF)도 프로그램을 종료한다.

대국 실행파일을 Windows Release로 빌드하고, 기존 코어 3개와 `console_test`를 합친 CTest 4개가 모두 통과했다. 콘솔 검증은 실제 실행파일에 7개 입력 세션을 보내 착수·오류 처리, 포획·자충수·집 판정 종료, 재시작과 재고 복원, 정상 종료를 확인한다. 실행파일의 DLL 의존성은 Windows 시스템 DLL만 남아 있으며 GCC 표준 런타임 DLL은 필요하지 않다.

### 기존 코어 검증 기록

2026-10-02 Windows에서 GCC 16.2.0, CMake 3.29.5, Ninja로 Release 빌드와 예제 실행을 확인했다. CTest의 3개 테스트가 모두 통과했으며, 보드 테스트에는 고정된 20개 시드의 무작위 대국을 끝까지 진행하여 합법 수, 중립 돌 보존, 돌 재고와 종료 상태를 확인하는 통합 검증이 포함된다.

후속 확정 규칙(자기 집 착수 금지, 41개 재고, 한 가장자리 집 인정)을 반영한 Release 빌드와 3개 테스트도 모두 통과했다. 자충수 설명에 사용한 좌상단 예시는 포획 테스트에서 기존 빈틈 1개, 가정한 착수 후 자기 무리 빈틈 0개, 상대 무리의 빈틈 잔존을 검증한다.

자충수 허용 후 즉시 패배를 기본값으로 확정한 뒤 Release 빌드와 3개 테스트가 모두 통과했다. 포획 테스트는 흑과 백 각각의 자충수 수락, 합법 수 목록 포함, 돌 재고 차감, 상대 승리와 이후 착수 금지를 검증한다. 양쪽 동시 포위 시 착수자 승리도 계속 검증한다.

## 순수 MCTS: 2026-10-02

`mcts/include/MCTS.h`와 `mcts/src/`에 신경망 없이 UCT와 무작위 완료 대국을
사용하는 MCTS를 구현한다. 사용자가 검증한 `engine/` 파일은 변경하지 않는다.
모든 실제 수는 기존 `State::play()`로 적용하며 포획, 자충수와 연속 패스
종료의 승자를 역전파한다. 상대 차례에는 상대 관점의 승률을 최대화한다.

`kingdom::MCTSOptions`에서 시뮬레이션 수, 탐색 계수, 난수 시드와 선택적 시간
제한을 지정하고 `MCTS::search(const State&)`로 추천 수와 후보별 방문 수·승률을
받는다. 전달한 게임 상태는 보존하며, 종료된 게임은 추천 수가 없다.
기본 규칙의 후보 수집은 공개된 보드·집 소유권·재고를 사용해 O(V)에 처리하고,
기존 O(V²) `legal_moves()`를 무작위 대국의 매 턴에 호출하지 않는다.

`examples/mcts_demo.cpp`의 `mcts_demo` 대상은 Windows에서 `MCTSDemo.exe`를
생성한다. 기본 실행은 초기 보드의 선공 추천 수를 1000회 탐색하며,
`--self-play [횟수]`는 양쪽 MCTS가 수마다 지정 횟수(기본 64회) 탐색하여 실제
종료까지 대국한다. 기존 `GreatKingdom.exe`에는 AI를 연결하지 않는다.
자세한 API, 탐색 방식, 복잡도와 실행 방법은 [mcts_design.md](mcts_design.md)에
기록한다. 성능은 해당 실행의 경과 시간과 시뮬레이션 수로 측정하며 목표 성능을
달성한 것으로 미리 표시하지 않는다.

## 신경망 PUCT: 2026-10-02

`mcts/include/PUCT.h`와 `mcts/src/PUCT.cpp`에 정책 사전 확률을 사용하는
PUCT를 별도로 구현한다. 트리 선택·확장·역전파는 C++에서 수행하고 새로운
비종료 상태의 정책·가치는 Python 콜백으로 PyTorch 모델에서 읽는다. 확정
포획·자충수·연속 패스 종료에는 모델을 호출하지 않고 실제 승패를 사용한다.
기존 순수 MCTS의 API와 실행 예제는 계속 무작위 완료 대국을 사용한다.

Python의 `kingdom_ai.PUCT`는 기존 스키마 1의 입력·출력을 사용한다.
`collect_puct_game`은 방문 비율과 최종 승패로 기존 `GameData` 형식의 학습
자료를 만들며 `make_batch`와 `train_step`에 바로 전달할 수 있다. 추천 검색은
루트 잡음을 끄고, 자료 생성에서는 선택적으로 루트 잡음과 방문 수 샘플링을
사용한다. 호출마다 새 트리를 구성하며 C++/LibTorch 직접 추론, 추론 배치와
대규모 반복 학습은 후속 작업이다. 사용자가 검증한 `engine/`는 변경하지 않는다.

`examples/puct_demo.py`로 추천 수 또는 종료까지의 자가 대국 자료 생성을
확인한다. 초기 가중치나 한 번만 갱신한 모델의 기력은 검증된 것으로 보지
않으며, 처리량은 실제 측정 조건과 함께 별도 기록한다.
