# 엔진 개발 계획

사용자가 2026-10-02에 지정한 개발 순서다. 규칙의 기준 문서는 [game_rules.md](game_rules.md)다.

## 1단계: C++ 엔진 코어와 순수 MCTS

- 9×9 보드, 선후공, 중앙 중립 돌, 턴, 패스, 종료 상태를 표현한다.
- 돌을 놓는 함수와 합법 착수 판정, 집 판정, 상대 돌 무리의 포위 판정, 즉시 승리와 연속 패스 후 점수 판정을 구현한다.
- 양쪽 동시 포위 시 착수자가 승리하는 우선순위를 지킨다.
- 신경망 없이 무작위 플레이아웃을 사용하는 순수 MCTS를 C++로 구현한다.
- 배열 보드의 규칙 정확성을 먼저 검증하고, 81개 지점을 비트 연산으로 처리하는 Bitboard 최적화를 적용한다. 81비트는 하나의 64비트 정수에 들어가지 않으므로 여러 워드 등 적절한 표현을 선택한다.
- 규칙 문서의 예시와 미확정 사항을 기준으로 검증한다. 일반 바둑의 패, 사활, 포획 후 대국 지속을 임의로 추가하지 않는다.

## 2단계: pybind11 Python 바인딩

- C++ 코어를 pybind11로 감싸 Python에서 `import my_board_engine`으로 호출한다.
- 플랫폼에 맞게 `.pyd` 또는 `.so`를 빌드한다.
- Python에서도 C++과 동일한 상태, 착수, 합법 수, 종료 및 승패 판정을 사용한다.

## 3단계: Python + PyTorch 신경망과 강화학습

- PyTorch 신경망을 구성한다.
- Python 학습 코드가 C++ 엔진을 호출하며 수십만 번의 대국을 생성하고 강화학습을 진행한다.
- 학습된 모델을 저장하고 대국 결과와 성능을 기록한다.
- 입력 표현, 모델 구조, 학습 목표 및 신경망과 MCTS 결합 방식은 이 단계에서 구체화한다.

## 4단계: C++ + LibTorch 자가 대국 최적화

- 저장한 PyTorch 모델을 C++ 코어에서 LibTorch로 직접 로드한다.
- Python을 거치지 않고 C++ 환경에서 신경망 추론, MCTS, 자가 대국을 실행한다.
- 완전한 C++ 학습 루프를 구성하려면 추론뿐 아니라 학습·체크포인트 저장도 이 단계에서 설계한다.

## 성능 목표와 관리

- C++의 실행 속도와 메모리 제어, Bitboard 연산을 활용한다.
- 사용자의 목표는 MCTS 시뮬레이션을 초당 수십만 번 수행하는 것이다. 이는 목표이며 측정된 성능이나 보장치는 아니다.
- 순수 무작위 플레이아웃과 신경망 추론을 포함하는 탐색을 구분하여 측정한다. 하드웨어, 탐색 횟수, 평균 대국 길이 등의 조건을 함께 기록한다.
- GitHub와 연결된 현재 저장소에서 규칙, 코드, 검증 결과, 개발 과정을 관리한다.

## 기록 시점의 저장소 상태

2026-10-02 확인 기준으로 엔진, MCTS, 테스트, 예제 파일 구조와 CMake 설정은 있으나 C++ 소스·헤더·테스트는 빈 파일이었다. 따라서 엔진 구현 완료로 표시하지 않는다. 이 문서 저장 작업에서는 엔진 구현이나 빌드 검증을 수행하지 않았다.
