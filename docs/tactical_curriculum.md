# 증명 기반 전술 보강 학습

`examples/train_tactics.py`는 기존 모델에 단수·축·장문·연결 문제를 보강한다.
`examples/train.py --online-tactics`는 새 자가 대국에서 발견한 위치를 매
사이클 증명하고 일반 학습 미니배치에 섞는 온라인 경로다.
문제 이름이나 사람이 둔 수를 정답으로 사용하지 않는다. 이 게임의 확정 규칙으로
C++ 전술 탐색기가 증명한 결과만 학습 목표로 채택한다. 기존 `engine/` 파일은
변경하지 않는다.

이 기능의 구현, 개별 문제의 증명, 모델의 문제 적합도, 실제 대국 기력은 서로
다르다. 깊이 12를 지정했다는 이유만으로 12수짜리 강제 포획을 증명했다고
보고하지 않는다. 실행별 증명 기록과 학습 전후 지표를 따로 확인한다.

## 바둑에서 참고하는 개념과 규칙의 경계

British Go Association(BGA)의 입문서는 활로를 상하좌우의 빈 인접점으로
설명하고, 돌 무리의 연결과 단수를 소개한다. 이 개념은 본 게임에서도 위협
위치를 살피는 데 유용하다. 실제 포획 여부는 항상 프로젝트 엔진으로 확인한다.
[BGA How to Play](https://www.britgo.org/intro/intro2.html)

BGA의 단계별 교육 자료에는 난이도별 문제 연습이 포함된다. 공식 문제 목록에는
끊기·연결, 가장자리 전술, 이중 단수, 축과 장문 등이 구분되어 있다. 여기서는
이러한 **교육 주제와 단계적 연습 방식**을 참고했으며, 외부 문제집의 보드·정답이나
일반 바둑 기보를 복제해 학습하지 않는다.
[BGA Junior Go Curriculum](https://www.britgo.org/junior/curriculum),
[BGA Go Puzzle Sheets](https://www.britgo.org/covers/psmith/index.html)

다음은 그 개념을 이 프로젝트에 적용한 설계다. 바둑의 규칙이나 정답을 그대로
이식한 것이 아니다.

| 주제 | 이 게임에서 연습하는 판단 |
| --- | --- |
| 활로와 단수 | 연결된 무리의 빈틈을 세고, 포획 가능한 마지막 활로를 확인 |
| 단수 방어·역포획 | 단순히 도망가는 수와 상대를 먼저 잡는 수를 구분 |
| 이중 단수 | 한 수가 여러 무리에 위협을 만들 때 상대의 모든 대응 확인 |
| 축과 축머리 | 단수를 연속으로 이어가는 추격, 다른 돌·중립 돌·가장자리에 따른 변화 |
| 장문 | 상대의 달아나는 길을 막는 포위 수와 국외 탈출 가능성 확인 |
| 연결과 끊기 | 따로 떨어진 무리를 연결하여 활로를 늘리거나 상대 연결을 차단 |

기본 게임에서는 상대 돌 한 개의 포획만으로 즉시 승리한다. 자충수는 착수를
허용하지만 즉시 패배하며, 상대 포획을 먼저 판정한다. 완성된 자기·상대 집에는
새 돌을 놓을 수 없다. 중앙 중립 돌, 각자 41개 재고, 연속 패스의 선공 집
3칸 차이 조건도 그대로 적용한다. 일반 바둑의 패 싸움·돌 희생 후 계속 대국·
사석 제거·덤 계산을 추가하지 않는다. 특히 일반 바둑의 두 눈 사활 설명만으로
이 게임의 안전이나 승리를 자동 판정하지 않는다. 기준은
[게임 규칙](game_rules.md)이다.

## 문제와 정답을 만드는 방식

`python/kingdom_ai/tactical_positions.py`가 직접 구성한 연습 문제와 사용자
대국의 기록 위치를 제공한다. JSON 문제에는 원본 식별자 `id`, 관련 문제를
묶는 `family_id`, 주제 `motif`, 위치 `position`이 들어간다.

- 대국 기록은 최초 상태부터 기존 `State.play()`로 재생한다. 보드 그림만 다시
  만들면서 누적 집 소유권·재고·패스를 잃어버리지 않는다.
- 새로 구성한 보드는 분석용 배치다. 해당 배열이 실제 대국에서 발생했다는
  의미는 아니다. 이미 활로가 없는 무리 등 잘못된 초기 위치를 거부한다.
- 사용자 대국에서 실제로 둔 수는 관찰 자료이지 최선 수의 라벨이 아니다.
- 기본 실행은 구성 문제와 사용자의 두 번째 대국의 관련 기록 위치를 검사한다.
  `--casebook`으로 별도 검증한 JSON 문제집을 추가할 수 있다.

전술 탐색은 깊이·노드·시간 예산 안에서 수행한다. 활로와 인접 위협은 탐색 순서를
정하는 데 사용할 수 있지만, 그런 휴리스틱으로 제외한 상대 응수를 없었던 것으로
취급하여 승리를 증명해서는 안 된다. 증명 결과는 현재 차례 플레이어 관점이다.

| 결과 | 의미 | 현재 보강 학습의 처리 |
| --- | --- | --- |
| `WIN` | 적어도 한 수가 상대의 모든 대응에도 승리함이 증명됨 | 비종료 위치의 증명된 승리 수로 정책, 가치 `+1` |
| `LOSS` | 모든 합법 수가 패배로 이어짐이 증명됨 | 보고서에 남기고 정책 모방 학습에서는 제외 |
| `UNKNOWN` | 예산·깊이 제한 등으로 증명이 끝나지 않음 | 학습에서 제외; 안전·패배·가치 0으로 라벨링하지 않음 |

정책 목표는 **알려진 증명 승리 수들**에 균등하게 분배한다. 이는 증명되지 않은
다른 합법 수가 모두 패배한다는 주장이 아니다. 실제 승리 수 전체보다 작을 수
있는 안전한 부분집합을 모방하는 현재 방식의 한계도 보고서에 명시한다.
`LOSS` 위치에서 아무 패배 수나 정답 정책으로 넣지 않으며, 현재 경로는 별도의
가치 전용 LOSS 학습을 하지 않는다.

원래의 `[10, 9, 9]` 입력과 82개 행동·현재 플레이어 관점 가치 출력은 유지한다.
활로 개념을 도입하면서 입력 채널이나 기존 모델 가중치 형식을 바꾸지 않는다.

## 기존 전략을 보존하는 학습과 평가

전체 학습 체크포인트가 제공되면 기존 replay에서 뽑은 위치를 함께 사용한다.
기본 128개 미니배치는 증명된 전술 32개(25%)와 원래 대국 위치 96개(75%)다.
replay는 표본 추출만 하고 기존 위치를 덮어쓰거나 전술 문제로 채우지 않는다.
`--tactical-fraction`으로 비율을 바꿀 수 있으며 반올림한 실제 행 수를 기록한다.
이 혼합은 기존 전략을 잊는 위험을 줄이려는 설계이지, 망각 방지를 보장하는
결과가 아니다.

추론용 모델만 제공하거나 replay가 비어 있으면 전술 비율은 실제로 100%가 된다.
보고서에 그 차이를 기록하며, 이 경우 일반 대국 전략의 유지 여부를 특히
별도로 확인해야 한다.

train/heldout은 회전·반사 전에 **원본 문제 가족 단위**로 나눈다. 인접한 사용자
기보 위치, 축과 축머리 변형, D4 회전·반사로 같은 위치가 되는 문제를 양쪽에
나누지 않는다. 학습 중에는 기존 대칭 증강을 사용하지만 지표는 증강하지 않은
원본 위치에서 계산한다. 독립 가족이 부족하면 heldout 지표를 비워 두며 학습
문제 암기를 일반화 성능으로 표시하지 않는다.

보고서의 `certified_top1`·`certified_top3`는 **신경망만** 평가하여 상위 수에
증명 승리 수가 포함되는 비율이다. 검색을 포함한 대국 승률이 아니다. 가치 MSE,
평균 가치, 손실도 함께 기록한다. 작은 heldout에서 개선하더라도 다양한 미학습
전술과 같은 탐색 예산의 대국 평가를 거치기 전에는 기력 향상으로 단정하지 않는다.

## 실행 예시

저장소 루트 PowerShell에서 새 바인딩과 Python 패키지를 빌드·설치한 가상환경을
사용한다. 다음은 명령 예시이며 실행 결과가 아니다. 출력 폴더가 이미 있으면
명령은 거부하므로 새로운 이름을 사용한다.

먼저 증명 자료만 확인하고 가중치 갱신을 하지 않는다.

```powershell
.\.venv\Scripts\python.exe examples\train_tactics.py `
  --resume-training runs\model-2026-10-07-1242i\latest.pt `
  --max-depth 9 --max-nodes 2000000 --time-limit-ms 2000 `
  --generation-seconds 60 --max-cases 64 `
  --dry-run `
  --output runs\tactics-proof-prepare-2026-10-07
```

`--dry-run`은 모델을 불러오거나 학습하지 않고 증명·원본 분리 보고서만 저장한다.
깊이 예산은 양쪽 착수를 합친 **ply** 단위다. 전역 생성 시간은 문제 사이에서
검사하므로 마지막 문제의 개별 시간 예산만큼 초과할 수 있다. `UNKNOWN`이 많으면
보고서의 예산·위치를 살펴 단계적으로 예산을 늘린다. 임의로 정답을 채우지 않는다.

전체 체크포인트에서 CUDA 보강 학습을 수행하는 예시는 다음과 같다.

```powershell
.\.venv\Scripts\python.exe examples\train_tactics.py `
  --device cuda `
  --resume-training runs\model-2026-10-07-1242i\latest.pt `
  --steps 256 --batch-size 128 --learning-rate 0.00003 `
  --tactical-fraction 0.25 --heldout-fraction 0.25 --seed 42 `
  --max-depth 9 --max-nodes 2000000 --time-limit-ms 2000 `
  --generation-seconds 60 --max-cases 64 `
  --output runs\tactics-candidate-2026-10-07
```

CUDA 자가 대국 설정이 저장된 전체 체크포인트는 `--device cuda`로 복원한다.
학습률은 공개 `Trainer.reconfigure()`로 변경하여 optimizer와 저장 설정이 일치한다.
이 값은 새 `latest.pt`를 재개할 때도 유지된다. `--seed`는 원본 가족 분리의 시드이며,
전체 체크포인트의 미니배치·대칭 표본 추출은 복원한 전용 Generator에서 이어진다.

추론용 가중치만 사용하려면 `--resume-training` 대신
`--initial-model runs\model-2026-10-07-1242i\best.pt`를 지정한다. 두 옵션은
동시에 사용할 수 없다. 추론 파일 경로는 새 Adam으로 모델 사본을 학습하며
기존 optimizer·replay·진행 횟수를 복원하지 않는다.

## 저장과 다음 단계

| 출력 | 내용 |
| --- | --- |
| `candidate.pt` | 보강한 learner의 추론용 가중치; 아직 champion이 아님 |
| `latest.pt` | 전체 체크포인트로 시작한 경우에만 저장하는 전체 학습 상태 (현재 v7) |
| `tactical_report.json` | 원본 SHA, 증명·제외 기록, 분리 가족, 손실, 학습 전후 지표와 시간 |

원본 `latest.pt`와 `best.pt`는 수정하지 않는다. 저장 폴더도 별도다.
기존 champion은 그대로 유지하며, 보강했다는 이유만으로 `best.pt`를 새 후보로
교체하거나 자동 승격하지 않는다. 보고서에 champion 가중치 보존을 확인한다.

v6는 전술 갱신 횟수를 `tactical_training_steps`로 별도 저장한다.
`training_steps`에는 실제 전체 Adam 갱신 수를 기록하고, 자가 대국 판수나 완료
사이클을 가짜로 늘리지 않는다. 자세한 호환성은
[반복 학습 체크포인트](training_loop.md#저장-파일과-재개-범위)를 참고한다.

새 `latest.pt`로 일반 학습을 이어가면 자가 대국은 아직 기존 champion으로
생성되고, 보강한 learner는 기존 optimizer와 함께 추가 학습·평가를 받는다.
전술 학습 완료가 자가 대국 모델의 즉시 교체를 뜻하지 않는다. 후보의 전술
실패 재현과 독립 대국 평가를 확인한 뒤 정상 승격 절차로 채택한다.

## 매 사이클 새로운 전술을 계산하여 학습하기

`train.py`의 `--online-tactics`를 켜면, 새 자가 대국이 끝난 뒤 그 대국의
비종료 위치 일부를 CPU C++ 증명 탐색기로 확인한다. 다음 순서로 기존 루프에
연결된다.

1. 기존 champion의 PUCT로 새 자가 대국을 생성하고 일반 replay에 저장한다.
2. 실제 착수 기록을 재생하여 선택한 위치의 집 소유권·재고·차례·패스를 보존한다.
3. 정해진 깊이·노드·시간 예산 안에서 강제 승리를 증명한다.
4. 채택한 증명 위치를 일반 replay와 분리된 전술 FIFO 버퍼에 넣는다.
5. 기존에 설정한 학습 갱신 횟수 안에서 전술 25%·일반 replay 75%를 혼합한다.
6. 기존 평가·champion 승격·전체 체크포인트 저장 절차를 그대로 수행한다.

이 연결은 **모든 실제 착수에 깊은 탐색을 추가하는 기능이 아니다.** 자가 대국
자체는 저장된 PUCT 예산(기존 실행에서는 128회)과 기존 얕은 전술 검사를
사용한다. 깊은 CPU 탐색은 사이클 후 제한된 위치에서 수행하는 학습용 teacher다.
콘솔 대국의 `--tactical-depth` 옵션이나 평가의 탐색 설정도 자동 변경하지 않는다.

teacher는 최소 증명 길이 조건을 만족하는 비종료 `WIN` 위치만 채택한다. 정책은
확실히 증명한 승리 수, 가치는 현재 플레이어 관점 `+1`이다. `LOSS`와
`UNKNOWN`, 깊이가 부족한 승리 위치는 증명 버퍼의 정책 목표로 넣지 않는다.
단, 이 위치가 일반 자가 대국 replay에 있는 경우 실제 대국의 방문 비율·최종
승패 목표로 학습하는 기존 경로는 유지한다. 모든 합법 방어를 고려한 증명과
실제 한 대국에서 관찰한 승패를 구분한다.

새로운 긴 승리 위치를 매 사이클 찾는다고 보장하지 않는다. 채택할 정답이 없으면
저장된 이전 증명 위치를 사용하고, 증명 버퍼도 비어 있으면 일반 replay만
학습한다. 기존 미니배치 크기와 `train_steps_per_iteration`은 늘리지 않으며,
온라인 혼합만으로 `tactical_training_steps`가 증가하지 않는다. 이 카운터는
`train_tactics.py`로 사이클 밖에서 추가한 Adam 갱신에만 사용한다.

기본 생성 예산은 사이클당 최대 32개 위치, 깊이 9수(ply), 위치당 2,000,000노드·
2,000ms, 생성 구간 30초다. 최소 증명 길이는 3수, 전술 버퍼 용량은 1,024개다.
시간 예산은 엄밀한 전체 사이클 wall-clock 상한이 아니며, 위치 수집·기록 재생·
버퍼 저장·마지막 탐색 등의 비용도 발생한다. `metrics.jsonl`에서 실제 teacher
시간과 증명·제외 개수, 전술 버퍼 크기, 실제 혼합 표본 수를 확인한다. 이 기능은
추가 CPU 계산이므로 원래 자가 대국 속도를 그대로 가정해서는 안 된다.

기존 v1~v6 체크포인트는 기본적으로 **온라인 전술 꺼짐·빈 증명 버퍼**로 복원된다.
기존 실행을 변경할 때는 `--reconfigure`와 새 출력 폴더가 필요하다. 먼저 아래
명령으로 기존 learner·champion·Adam·일반 replay·진행 횟수를 보존하면서
온라인 teacher 설정만 준비한다. 이 단계에서는 대국이나 추가 학습을 시작하지
않는다. 출력 폴더에 기존 학습 파일이 있으면 새로운 이름을 사용한다.

```powershell
.\.venv\Scripts\python.exe examples\train.py `
  --resume runs\tactics-candidate-2026-10-07\latest.pt `
  --device cuda --reconfigure --prepare-only `
  --online-tactics `
  --online-tactics-max-cases 32 --online-tactics-max-depth 9 `
  --online-tactics-max-nodes 2000000 --online-tactics-time-limit-ms 2000 `
  --online-tactics-generation-seconds 30 --online-tactics-fraction 0.25 `
  --online-tactics-replay-capacity 1024 --online-tactics-min-proof-depth 3 `
  --output runs\tactics-online-2026-10-07
```

준비한 새 체크포인트를 재개하면 설정과 전술 버퍼도 함께 복원한다. 다음 명령은
10사이클을 추가하는 예시다. `--online-tactics` 등의 학습 설정을 다시 지정하지
않는다.

```powershell
.\.venv\Scripts\python.exe examples\train.py `
  --resume runs\tactics-online-2026-10-07\latest.pt `
  --device cuda --iterations 10 --output runs\tactics-online-2026-10-07
```

새 실행에서는 `--online-tactics`를 직접 지정할 수 있다. 지정하지 않으면 이전
동작을 유지한다. 기존 온라인 실행을 끄려면 다시 새 출력 폴더와
`--reconfigure --no-online-tactics`를 사용한다. 설정 변경은 저장 경계에서만
가능하며, 이미 채운 전술 FIFO의 용량을 임의로 바꾸어 자료를 버리지 않는다.
최신 저장 형식과 재개 조건은 [반복 학습 안내](training_loop.md)에 있다.

## 실제 검증과 추가 학습: 2026-10-07

`runs/model-2026-10-07-1242i/latest.pt`를 복원하여 새 폴더
`runs/tactics-candidate-2026-10-07/`에 저장했다. 깊이 9, 최대 2,000,000노드,
문제당 2,000ms, 전체 생성 예산 60초를 지정한 실제 실행이다.

사용자 두 번째 대국의 흑 17번째 착수 `(4,4)` 직후에서 백의 승리를 증명했다.
987,669노드, 1,115.5ms, 증명 수순 길이 9다. 원래 기록을 따라간 것만이 아니라
상대 차례의 모든 합법 응수를 포함해 승리를 증명한다. 대표 수순은 다음과 같다.
좌표는 1부터 시작하며, 양쪽의 착수를 합친 9수다.

```text
백(4,3) → 흑(5,4) → 백(6,4) → 흑(5,3) → 백(5,2)
→ 흑(6,3) → 백(7,3) → 흑(6,2) → 백(6,1): 흑 7개 포획
```

이는 기록의 마지막 흑 `(3,3)`·백 `(6,2)`에서 흑 6개를 잡은 수순과 다르다.
증명 PV는 가능한 방어의 한 대표이며, 최단 승리 수순이나 전체 증명 트리를
출력했다는 의미가 아니다. 깊이 12/100,000노드와 깊이 12/2초에서는 같은
시작점이 `UNKNOWN`이었다. 제한 시간에서 큰 깊이가 항상 더 많은 문제를
해결하는 것은 아니다. 현재 탐색은 반복 심화나 proof-number search가 아닌
깊이 제한 minimax다. 별도 11수 축 예시는 아직 증명하지 못했다.

| 실제 실행 항목 | 결과 |
| --- | --- |
| 검사한 원본 위치 | 직접 구성한 문제 17개 + 사용자 기록 위치 12개 |
| 증명 결과 | WIN 13개 / LOSS 4개 / UNKNOWN 12개 |
| 분리 | 학습 11개 / 독립 원본 가족 heldout 2개 |
| Adam 갱신 | CUDA 256회, 미니배치 128, 학습률 0.00003 |
| 각 미니배치 | 전술 32개 + 기존 replay 96개, 대칭 증강 |
| 기존 replay | 131,072개 위치 유지 |
| 학습 문제의 신경망 top-1 | 8/11(72.7%) → 11/11(100%) |
| heldout의 신경망 top-1 | 2/2 → 2/2 |
| 학습 문제 가치 MSE | 0.4566 → 0.0197 |
| Adam 갱신 시간 | 3.762초 |
| 자료 생성·복원·훈련·저장 전체 | 39.802초 |

9수 증명 위치와 후반 5수·3수·1수 포획 위치가 학습 쪽에 포함되었다. 초기 판면,
축머리, 연결 등의 미확정 위치를 정답으로 채우지 않았다. 특히 heldout 2개는
짧은 포획 문제라서 긴 수읽기 일반화의 증거가 아니다. 위 100%는 학습 문제
적합도이며 새로운 8수 이상 위치를 모두 해결한다는 뜻이 아니다.

추가 학습은 완료 사이클 484와 자가 대국 991,232판을 그대로 두고,
총 갱신 61,952 → 62,208, 전술 갱신 0 → 256만 증가시켰다. checkpoint v6로
저장·복원할 수 있다. 원본 파일 SHA와 champion 가중치 SHA가 실행 전후 같다.

후보를 기존 `best.pt`와 20판 평가했다. 양쪽 128회 탐색, 흑백 각 10판,
시드 20261007, 시작 6수 온도 1, CUDA 추론, `batched_cpp` 4workers,
leaf batch 8, 트리 재사용으로 맞췄다. 양쪽 모두 추가 깊은 증명 탐색 없이
기존 탐색으로 **후보 8승 12패(40%)**였다. 이 작은 실험에서 전체 기력 우위를
확인하지 못했으므로 champion으로 승격하지 않았다. 원본 learner와 동일 시드로
비교한 전후 대결은 아니므로 학습 때문에 일반 기력이 떨어졌다고도 단정할 수 없다.
추가 학습과 아래 명령의 깊은 수읽기 보강은 별개 기능이다.

상세 기록:

- `runs/tactics-candidate-2026-10-07/tactical_report.json`
- `runs/tactics-candidate-2026-10-07/match-vs-champion-20.jsonl`

새 후보를 콘솔에서 시험하면서 깊은 수읽기를 함께 켜려면 다음 명령을 사용한다.
기본 `--tactical-depth 0`은 기존 동작을 유지한다. 아래 설정은 한 수당 최대 약
2초의 추가 CPU 증명 예산을 사용하며, 전체 AI 탐색 시간 상한은 아니다.

```powershell
.\.venv\Scripts\python.exe examples\play_ai.py `
  --checkpoint runs\tactics-candidate-2026-10-07\candidate.pt `
  --device cuda --simulations 128 `
  --tactical-depth 9 --tactical-node-budget 2000000 --tactical-time-ms 2000
```

안정된 기준 모델을 유지하며 수읽기만 보강하려면 `--checkpoint`를 기존
`runs\model-2026-10-07-1242i\best.pt`로 바꾼다. 이 옵션은 현재 콘솔 CPU/GPU
대국에 연결했으며, 모든 UI·평가·자가 대국에 자동 적용한 것이 아니다.

새 학습 상태에서 일반 자가 대국을 이어갈 때는 별도 폴더를 사용한다. 다음은
실행 예시이며 위 일회성 전술 보강 작업에서는 추가 일반 사이클을 실행하지 않았다.

```powershell
.\.venv\Scripts\python.exe examples\train.py `
  --resume runs\tactics-candidate-2026-10-07\latest.pt `
  --device cuda --iterations 10 --output runs\tactics-rl-2026-10-07
```

Release 빌드 및 CTest 36개 묶음을 검증했다. 샌드박스의 localhost 연결 차단으로
실패한 기존 UI 2개는 권한을 허용한 재실행에서 통과했고, 나머지 34개는 기본
환경에서 통과했다. 실제 CUDA의 깊은 패배 수 필터를 포함한 Python 전술 선택
14개도 별도로 통과했다. `engine/` 소스 변경은 없다.

가상환경에 새 패키지를 오프라인 빌드·설치한 뒤 `PYTHONPATH`를 제거하고도
v6 `latest.pt`의 `(iteration=484, games=991232, updates=62208, tactical=256,
champion_version=171)` 복원을 확인했다. 저장된 `candidate.pt`가 learner와 같고,
설치된 C++ 바인딩에서도 동일한 987,669노드·9수 WIN 증명을 재현했다.

## 온라인 연결 실측: 2026-10-07

위 전술 보강 상태를 보존하여 `runs/tactics-online-2026-10-07/latest.pt`에
온라인 teacher를 켠 v7 상태를 준비한 뒤, 일반 CUDA 학습을 **1사이클만**
실행했다. 일회성 문제집을 다시 넣는 대신 이번에 생성한 실제 대국에서 위치를
수집했다. RTX 3050에서의 이번 실행 결과이며 일반적인 처리량 보장은 아니다.

새 9수 증명은 `online_cycle_485_game_991839_ply_32`에서 생성되었다.
대표 수순은 흑 `(6,4)` → 백 `(5,3)` → 흑 `(5,4)` → 백 `(4,3)` →
흑 `(6,5)` → 백 `(7,6)` → 흑 `(8,1)` → 백 `(6,1)` → 흑 `(5,1)`이며,
상대 응수들을 포함한 승리 증명의 한 PV다. 최단 승리 수순이라고 주장하지 않는다.
미확정 15개와 증명된 패배 5개는 교사 정책 정답에서 제외했다.

진행은 `(iteration=485, games=993280, training_steps=62336,
tactical_training_steps=256, champion_version=171)`이다. 온라인 혼합은 기존
사이클 갱신 안에서 이루어져 별도 추가 갱신 카운터 256은 늘지 않았다.
원본 `tactics-candidate-2026-10-07/latest.pt`의 SHA256은 실행 전후
`753b7c45be0d886da9baf1dfc1d2c86085130c929bbbb41dc88d04a7175cf26a`로 같다.

이 한 사이클은 자료 생성·혼합·저장이 연결되었음을 확인한 실행이다. 새 위치의
전술 정확도나 전체 기력이 개선되었다는 검증은 아니다. 증명 자료가 적을 때의
반복 학습과 장기 전술 일반화는 후속 별도 평가가 필요하다. 계속 학습할 때는
위 온라인 재개 명령을 사용하고, `metrics.jsonl`의 `online_tactics`에서 신규
채택 수·제외 결과·실제 시간·혼합 수를 확인한다.

온라인 연결 후 CTest 39개 묶음을 검증했다. 기본 샌드박스에서 37개가 통과했고,
localhost 연결 제한으로 실패한 기존 UI 2개는 해당 권한을 허용한 재실행에서
모두 통과했다. CPU·실제 CUDA 착수 기록, 증명 채택·제외, 기존 갱신 수 유지,
v1~v6 호환과 v7 전술 FIFO·난수 복원을 포함한다. `engine/` 소스 변경은 없다.
새 패키지를 가상환경에 오프라인 설치하고 `PYTHONPATH` 없이 CUDA로 위 상태와

`model-2026-10-07-1242i/best.pt`와 일치한다.
