# 기력 개선과 재개 설정: 2026-10-06

## 확인한 문제

`gpu-r1-tuned/latest.pt`의 완료 243사이클은 자가 대국 497,664판, 생성 위치
7,699,640개, Adam 갱신 31,104회, 학습 위치 복원추출 15,925,248회다.
따라서 단순히 학습 갱신 수가 적다고 설명할 수 없다.

현재 버퍼의 게임 시작점 9,056개 중 9,029개는 흑 승리였다(99.70%).
모든 시작점의 정책 목표는 한 칸에 방문 비중 100%였고, 기준 모델은 첫 수
6행 8열에 약 99.9997%를 부여했다. 보드를 보지 않고 흑 +1, 백 -1만 출력해도
현재 버퍼의 가치 MSE는 0.02509로, 최근 실제 손실 0.01882와 비슷하다.
이는 강한 기력의 증거가 아니라 편향된 자료에서도 손실이 낮아지는 상황이다.
원본과 기간별 수치는 [학습 감사 JSON](benchmarks/strength_audit_2026-10-06.json)에 있다.

기존 탐색에서 미방문 후보의 Q는 0이다. 거의 한 칸인 prior와 흑에게 유리한
가치 예측이 결합하면 다른 후보를 방문하지 못한다. 착수 온도가 1이어도 방문
0인 수는 뽑지 않으므로 온도만 늘려서는 이 문제를 해결하지 못한다.

## 즉시 적용되는 전술 확인

사람 대 AI 프로그램은 CPU/CUDA 모두 기본으로 다음을 확인한다.

1. 우리에게 즉시 승리하는 수가 있으면 그 수를 우선한다.
2. 그렇지 않으면 자충·두 패스 즉시 패배와 상대 다음 한 수 포획·패스 승리를
   허용하는 수를 제외한다.
3. 안전한 수가 하나도 없다면 기존 합법 후보 안에서 탐색한다.

실제 규칙의 합법 수를 변경하지 않고 루트의 선택 후보만 좁힌다. 상대의
포획 응답은 돌무리의 마지막 자유공간을 찾아 실제 규칙 판정으로 검증한다.
여러 수 뒤의 이중 위협이나 승리를 완전히 읽는 기능은 아니다.

사용자 수순(1부터 시작하는 행·열)은
`4 8, 5 8, 2 8, 6 8, 2 4, 4 4, 6 2, 4 7, 3 7, 5 9, 4 6`이다.
다음 백 수의 유일한 안전 후보는 **5행 7열**이다. 기존 백의 4행 9열은
흑 5행 7열 한 수로 백 4행 7열 돌을 잡히게 했다.

동일한 기존 모델, GPU 탐색 128회에서 이 방어 위치의 8대칭은 기존 0/8에서
수정 후 8/8, 즉시 포획 위치 8대칭은 6/8에서 8/8로 개선됐다. CPU와 GPU
대국 경로에서도 해당 안전 수를 반환하는 것을 확인했다.
[전술 실측 JSON](benchmarks/strength_tactics_2026-10-06.json)에 환경과 모델 해시가 있다.

설치된 가상환경에서 사용자 명령을 그대로 다시 실행하면 전술 확인이 적용된다.
GPU는 FPU 0도 기본으로 사용한다. 비교하려면 `--no-tactical-checks`를 사용할 수
있으며 GPU의 `--fpu-reduction`은 미방문 Q를 신경망 가치에서 얼마나 낮출지 정한다.

```powershell
.\.venv\Scripts\python.exe examples\play_ai.py --checkpoint runs\gpu-r1-tuned\best.pt --human black --device cuda
```

## 학습 설정

새 체크포인트 `runs/gpu-strength-v2/latest.pt`를 준비했다. 기존 가중치,
기준 모델, Adam 모멘트와 31,104회 갱신, 버퍼 131,072개, 진행 243사이클,
497,664판과 난수 상태를 유지한다. **추가 생산 학습은 시작하지 않았다.**

| 항목 | 이전 | 새 설정 |
| --- | ---: | ---: |
| 반복당 자가 대국 / 동시 대국 | 2048 / 1024 | 2048 / 1024 |
| 탐색 / 미방문 Q | 32회 / 0 | 128회 / 해당 노드 신경망 가치 |
| 전술 확인 | 없음 | 즉시 승리·한 수 패배 확인 |
| 자료 증강 | 없음 | 위치마다 회전·반사 8종 중 하나 |
| 착수 온도 | 항상 1 | 첫 8수 1, 이후 0.25 |
| 학습 배치 × 갱신 | 512 × 128 | 512 × 128 |
| 학습률 | 0.001 | 0.0003 |
| 평가 / 탐색 | 20판 / 32회 | 40판 / 128회 |
| 승격 기준 | 55% | 60% |

증강은 보드·합법 마스크·정책을 같은 방향으로 변환하고 패스와 승패를 유지한다.
배치를 여덟 배로 복제하거나 저장 용량을 늘리지 않는다. 온도는 실제 착수
추출에만 적용하고 정책 목표는 원래 방문 비율로 유지한다.

초기 위치 32개에서 잡음 0.25, 탐색 128회로 비교한 평균 방문 후보 수는
FPU 적용 전 1.03개에서 FPU 0 적용 후 12.59개였다. 최고 후보의 방문 비중은
99.78%에서 88.45%로 낮아졌다. 최선 수는 여전히 같았으므로 초기 착수의
다양성이 완전히 해결됐다는 결과는 아니다.

새 설정으로 한 사이클을 진행하는 명령:

```powershell
.\.venv\Scripts\python.exe examples\train.py --device cuda --resume runs\gpu-strength-v2\latest.pt --evaluation-workers 12 --iterations 1 --output runs\gpu-strength-v2
```

탐색량과 평가를 늘렸으므로 이전 처리량 12~42판/초를 보장하지 않는다.
현재 준비 파일은 버전 3이라 첫 실행에서 worker 12를 명시한다. `Trainer.run()`은
대국 전에 이 값을 포함한 버전 4 경계를 저장하므로 이후 재개에서는 자동 복원한다.
동일 모델 20판·32회 탐색의 축소 측정에서 12 worker는 순차 71.94초를
26.42초로 줄였지만, 이 값은 위 40판·128회 전체 사이클의 실측값이 아니다.
더 안전한 대국이 오래 지속될 수도 있다. 기존 버퍼는 다음 생성 자료로 FIFO
교체되며, 새 자료가 131,072개를 넘으면 일부는 학습 전 밀려날 수 있다.
관측할 지표는 색별 승률, 초기 정책의 방문 후보 수, 평균 수순, 독립 상대
평가와 실제 포획·방어 실수다. 외부 AI 상대 재대결 승률은 아직 측정하지 않았다.

## 설정 변경과 저장 형식

`--resume --reconfigure --prepare-only`는 추가 대국 없이 새 설정을 저장한다.
반드시 새로운 `--output`을 지정해 원본을 보존한다. 예를 들어 다른 기록에서
같은 변경을 준비하려면:

```powershell
.\.venv\Scripts\python.exe examples\train.py --device cuda --resume runs\gpu-r1-tuned\latest.pt --reconfigure --prepare-only --simulations 128 --augment-symmetries --temperature-moves 8 --final-temperature 0.25 --self-play-tactical-checks --self-play-fpu-reduction 0 --learning-rate 0.0003 --eval-games 40 --eval-simulations 128 --promotion-threshold 0.6 --output runs\gpu-strength-new
```

카운터와 자료 일관성을 위해 반복당 판수, 반복당 갱신 횟수, 버퍼 용량과 seed는
이 방식으로 변경하지 못한다. 설정 변경은 완료한 반복의 경계에서만 허용한다.
가중치·optimizer·버퍼를 초기화하지 않는다.

현재 코드는 체크포인트 버전 4를 쓰며 버전 1~3을 계속 읽는다. 버전 4는 평가
worker를 저장하고 이전 파일에는 이 값이 없어 순차 worker 1로 복원한다.
버전 3보다 이전 파일에 새 기력 옵션이 없으면
증강 없음·온도 스케줄 없음·전술 확인 없음·기존 미방문 Q=0으로 복원한다.
대국 프로그램의 전술 확인 기본값과 이전 학습 파일의 기본값은 별개다.
모델 입력/출력 스키마는 유지했고 `engine/` 파일은 변경하지 않았다.
